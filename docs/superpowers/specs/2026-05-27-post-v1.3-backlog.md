# Post-v1.3 Backlog — Enhancements + Mini-features

**Status:** Backlog. Not a single design — a curated, filtered candidate pool to draw from
in future brainstorming sessions.
**Author:** Claude + Louay
**Date:** 27 May 2026
**Parent state:** v1.3 shipped to TestFlight (build 1.3.0 (1)). v1.4 quality-of-life spec
approved and ready for implementation (`2026-05-27-v1.4-quality-of-life-design.md`).

## Purpose

This document is a curated list of work items worth doing on Cadence after v1.3
ships, separate from the v1.4 polish bundle and the long-horizon portfolio
(Stripe payment links, full expenses, quarterly tax).

It is **not** an implementation plan. Each item is sized but not designed.
Pick an item and run the brainstorming skill on it to produce a real design doc.

## Filter rules applied

Removed during ideation:

- Already in v1.4 spec: Recent tile removal, Currency moved to Settings,
  About attribution, Bank details on PDF invoice.
- Already shipped in v1.x: Recurring invoices, CSV export, ISO-4217 currency picker,
  Resume pill, Live Activity, widgets, App Intents, CloudKit mirror.
- Already in long-term portfolio (too big to be "mini-features"): Stripe payment
  links via Connect Express, full expenses with categorization/mileage, quarterly
  tax estimate.
- Intentionally cut from v1 for a good reason and still not worth reopening:
  multi-currency per-invoice, team/collaboration, screenshot monitoring, payroll,
  full receipt OCR, multiple invoice templates.
- Cosmetic-only without behavioral value: app icon picker, sound effects, theme
  accent color, custom haptic toggles.

Sizing legend: **XS** = hours · **S** = half-day to a day · **M** = 2-3 days.

## Appendix — detailed item specs

The tables above are the source of truth for "which items exist and where they
live." The sections below provide implementation sketches for each item, ready
to be lifted into a per-item brainstorm session.

### A1 — Logo upload on Business Profile, rendered in PDF header — S

FEATURES.md says the invoice template renders "logo if uploaded" in the header
row, but the editor surface has no upload affordance. Either the feature is
wired but unreachable from UI, or it's documented intent that was never built.

Implementation sketch: `PhotosPicker` on Business Profile editor → resize to
1024px square max → store as `Data?` on `BusinessProfile` → snapshot to
`Invoice.issuerLogoSnapshot: Data?` at finalization → draw in the existing PDF
header's left side. Follows the same snapshot pattern as v1.4 bank details.

### A2 — Tax ID / VAT number on Business Profile + PDF — S

Implementation sketch: two strings on BusinessProfile (`taxIDLabel: String`
e.g. "VAT", "GST", "CR No."; `taxIDNumber: String`). Snapshot pair on Invoice.
Render under the issuer address block in the PDF header. Pairs with the v1.4
bank details work because both touch the BusinessProfileEditor + PDF template
+ Invoice snapshot pattern.

### A3 — Customizable invoice email subject + body templates — S

Implementation sketch: two `TextEditor` fields on Business Profile (subject
template, body template). Merge fields: `{clientName}`, `{invoiceNumber}`,
`{amount}`, `{dueDate}`, `{senderName}`. Existing `ReminderTemplateRenderer`
(BillableCore) handles the merge-field substitution already — extend the
template field set, or build a sibling renderer for share-invoice flow.

### A4 — Inline note field on the running timer card — XS

Currently `TimeEntry.notes` is only editable on a stopped or manually-created
entry.

Implementation sketch: bind a `@Bindable` `TextField` ("What are you doing?")
inside `RunningTimerCard`. Throttle saves via `.onChange` debounce so we don't
SwiftData-save on every keystroke.

### A5 — Adjust start time on a running entry — XS

Implementation sketch: `Menu` or `ConfirmationDialog` on tap of the elapsed
counter, three quick offsets (back 5 / 10 / 15 min) plus "Adjust to…" opening
a `DatePicker`. Mutates `runningEntry.startedAt`. Edge: must remain `< Date.now`.

### A6 — "Avg hourly rate" + "Top client" tiles on Reports — XS

Implementation sketch: two pure-presentation tiles wired to existing
`ReportsAggregator` output. Avg rate = `totalEarned / totalBillableSeconds * 3600`.
Top client = sort `hoursByClient` by amount desc, take first.

### A7 — "Days since last invoice" badge on each client row — XS

Implementation sketch: compute `lastInvoiceDate` per client via SwiftData
predicate (Invoice where `clientID == client.id`, sortBy sentAt desc, first).
Show "Last invoice: X days ago" as a subtle subtitle on the client row.
Skip the badge if no invoices have ever been sent for that client.

### A8 — Inline edit of draft line-item descriptions before finalizing — S

Implementation sketch: `InvoiceDetailView` for `status == .draft` shows each
line item with an editable description field. Save updates the `lineItemsData`
JSON blob on the draft invoice. Hours / rate / amount columns remain read-only.

### A9 — Per-client default reminder offsets — S (verify first)

The v1.1 reminders spec mentioned per-client reminder offset override as Phase
5 work. Worth verifying whether it actually landed.

Implementation sketch: First check `App/Sources/Features/Clients/ClientEditorView.swift`
and `Packages/BillableCore/Sources/BillableCore/Models/Client.swift` for an
existing `reminderOffsets` field. If present and wired into `ReminderService`,
nothing to do — close the item. If absent or unwired, ship the editor section
plus the service lookup ("if client.reminderOffsets is non-empty, use them;
else fall back to ReminderConfig defaults").

### A10 — Sweep `@Query` and `FetchDescriptor` for missing fetch bounds — XS

Same pattern as the perf fix shipped on 2026-05-27 in `TodayView` (commit
`f9fff44`).

Implementation sketch: `grep -rn "@Query\|FetchDescriptor" App Packages`,
inspect each consumer, add `fetchLimit` where appropriate. Likely 5-10 sites.
Group the changes into a single commit with a brief summary.

### B1 — Estimates / quotes — M

A "quote" is functionally an invoice without time entries: manually-typed
line items, a tax/total, marked "Quote" instead of "Invoice", no eligibility
filter. Reuses ~90% of the existing PDF template and renderer pipeline.

Implementation sketch: new `Quote` @Model (sibling to Invoice, similar
snapshot pattern). New "Quotes" segment on the Invoices tab. New quote editor
(client + manually-typed line items + tax + notes). New "Convert to invoice"
action that creates a Draft Invoice pre-populated with the quote's line items.
PDF reuses the existing template with a "QUOTE" wordmark instead of "INVOICE".

### B2 — Rate change effective-date on Project — M

Real-world: clients agree to a retainer raise ("from January, rate goes from
$80 to $95"). The current workaround is to make a new project (loses history)
or live with mixed-rate weirdness.

Implementation sketch: new `RateChange` model with `effectiveDate: Date` +
`hourlyRate: Decimal`, owned by Project. TimeEntry.amount computation looks up
the project's rate as of `startedAt`. UI: a "Rate history" subsection on the
project editor with add/remove rows. Migration: existing project rate becomes
a single RateChange with `effectiveDate = .distantPast`.

### B3 — "What did I track today?" Siri intent — XS

Implementation sketch: new `AppIntent` returning `IntentResult & ProvidesDialog`.
Aggregator queries today's `TimeEntry` rows from the shared App Group store,
formats hours + dollars + top client names, returns `.result(dialog: ...)`.
Donate on first invocation so Siri learns the phrasing.

### B4 — Stop button in Live Activity / Dynamic Island — XS

Implementation sketch: in the Live Activity widget (in `Widgets/`), wrap the
trailing area in a `Button(intent: StopTimerIntent())` with a stop icon.
Existing `StopTimerIntent` is reused as-is. Requires iOS 17.0 baseline (already
the project minimum).

### B5 — watchOS minimum-viable companion — M

One screen: currently-running timer + Stop button + "Start last project"
quick action. Complication: small ring/text with elapsed seconds. No editing,
no timeline, no invoicing.

Implementation sketch: new watchOS target. Shares `BillableCore` package.
Reads/writes the same App Group + CloudKit-mirrored SwiftData store. Single
SwiftUI view + complication. WatchConnectivity not required because both
devices write to CloudKit and read on each side.

### B6 — Pinch-to-zoom on Timeline (hour density 60/80/120 pt) — S

Implementation sketch: `MagnificationGesture` on the timeline canvas mutates
a `@State` pt-per-hour value. Clamp to `[60, 120]`. Persist last-used value
to `@AppStorage`. All existing block layout math already scales off a single
`pointsPerHour` constant — refactor it to a variable.
