# Cadence v1.2 — Soft Paywall + 7-Day Trial

**Status:** Design approved · ready for implementation plan
**Date:** 2026-05-26
**Phase:** v1.2 (post-v1.1.2, supersedes the archived Stripe-Connect v1.2)
**Estimated scope:** ~3-4 working days
**Spec author session:** brainstorming flow (superpowers:brainstorming) with visual companion

---

## 1. Summary

Reshape Cadence's monetization model from "restrictive free + paywall everywhere" to "soft paywall + 7-day trial + watermarked free invoices." The free tier becomes genuinely useful so users stick around past day 1; Pro becomes the natural upgrade for professional polish (no watermark) and analytical depth (Reports + CSV).

**Five concrete changes:**

1. **Add a 7-day free trial** via Apple's StoreKit introductory offer mechanism. Configured in `Billable.storekit`. App Store handles the trial timer + auto-charge on day 8. No custom Swift state machine needed.

2. **Add a `.trial(daysRemaining:)` case** to the `Entitlement` enum on `SubscriptionManager`. Three states: `.trial`, `.pro`, `.free`. State is derived from StoreKit transactions, not persisted independently.

3. **Open up the free tier:** drop the 2-client cap; allow free users to issue invoices (watermarked) + use Recurring + Reminders. Reports tab and CSV export remain Pro-only.

4. **Watermark free invoice PDFs** with "Sent with Cadence" in 9pt italic gray, footer-centered. Pro entitlement removes the watermark.

5. **Simplify paywall triggers:** `createInvoice` and `extraClient` triggers are removed (no longer paywall-worthy). `reports` and `settings` triggers stay. A new `removeWatermark` trigger surfaces on the invoice preview when a free user wants the watermark gone.

**Plus:** replace the `example.com` placeholder Terms + Privacy URLs in `PaywallView` with real production URLs (user-provided; documented as a parallel deliverable).

---

## 2. Goals & non-goals

### Goals
- A free user can experience the full wedge (track → review → invoice) without hitting a paywall. They send a watermarked PDF to their client; the watermark creates organic upgrade pressure.
- A new user gets 7 days of full Pro to evaluate Reports + watermark-free invoices before committing.
- Apple handles all the heavy lifting for trial timing, auto-renewal, and refunds.
- No new `@Model` types. No new migrations. No custom monthly meter.
- Existing v1.1.2 paywall structure (PaywallView layout, copy, pricing) stays — only specific copy strings and trigger-handling logic change.

### Non-goals (deferred)
- **Visual paywall redesign** (layout, hierarchy, brand icon swap) — stays as v1.1.2 ships. Future polish task.
- **Pricing changes** — $5.99/mo + $34.99/yr unchanged.
- **Monthly invoice meter** ("1 free per month") — explicitly rejected during brainstorming. Soft paywall + watermark is the chosen mechanism.
- **Forced Business Profile onboarding** — v1.1.2's banner + disabled-Send pattern stays.
- **Payment provider integration** (PayTabs etc.) — separate spec when ready.
- **VAT, Arabic RTL, Hijri dates** — separate KSA-launch spec.
- **App Store metadata / submission assets** (screenshots, listing copy, age rating) — parallel user-side work outside this spec.

### Forward references (acknowledged, not designed here)
- The watermark renderer is the natural extension point for any future "branding" Pro perk (custom logo, color schemes, etc.).
- The `Entitlement` enum's three states are the foundation for any future Pro-tiered features (e.g. "Pro+ for teams").
- The `removeWatermark` trigger pattern (paywall opens from a feature button) can be reused for any other free-tier limitation.

## 3. Per-change design

### Change 1 — Add 7-day trial to StoreKit Configuration

**File:** `App/Resources/Billable.storekit`

For BOTH the monthly and yearly products, set `introductoryOffer` to:

```json
{
  "displayPrice" : "0.00",
  "internalID" : "<UUID>",
  "numberOfPeriods" : 1,
  "paymentMode" : "free",
  "subscriptionPeriod" : "P1W"
}
```

(`P1W` = 1 week = 7 days. `paymentMode: "free"` = no charge during the intro period. Apple charges the regular price starting day 8.)

The Task 1 of v1.1.2 removed an existing 7-day intro offer because the v1.1.2 spec said no trial work; that decision is reversed here. The reintroduced offer must be on BOTH subscriptions (not just yearly) so users can choose either tier and get the same 7-day evaluation window.

**Acceptance:** Open `Billable.storekit` in Xcode → both products show "Free trial · 1 week" under their pricing. Run app on simulator → paywall surfaces a "Start 7-day free trial" button.

### Change 2 — Expand `Entitlement` enum on `SubscriptionManager`

**File:** `Packages/BillableCore/Sources/BillableCore/Subscriptions/SubscriptionManager.swift`

Current state (post-v1.1.2): `SubscriptionManager` exposes `isProUser: Bool` (or similar), derived from a single StoreKit transaction lookup. Replace with a richer `Entitlement` enum:

```swift
public enum Entitlement: Equatable, Sendable {
    case free
    case trial(daysRemaining: Int)
    case pro
}

public var entitlement: Entitlement {
    // Derive from StoreKit current entitlements:
    // - If there's an active subscription transaction with `purchaseDate` in
    //   the last 7 days AND the user is on the introductory offer period:
    //     → .trial(daysRemaining: ceil((7 - daysSincePurchase)))
    // - Else if there's an active subscription transaction (post-trial):
    //     → .pro
    // - Else:
    //     → .free
}

public var canRemoveWatermark: Bool {
    switch entitlement {
    case .free: return false
    case .trial, .pro: return true
    }
}

public var canAccessReports: Bool {
    switch entitlement {
    case .free: return false
    case .trial, .pro: return true
    }
}
```

`daysRemaining` is for UI display only ("Day 3 of 7" banner — optional, not required for v1.2). The auto-renewal happens at the App Store level; we don't track the timer ourselves.

**Acceptance:**
- New user → `entitlement == .free` (no transactions exist yet).
- User completes trial purchase → `entitlement == .trial(daysRemaining: 7)` immediately, decrementing to `.trial(daysRemaining: 6)` after 24h, etc.
- Day 8 (after auto-charge) → `entitlement == .pro`.
- User cancels trial mid-period → still `.trial(daysRemaining: X)` until day 7, then drops to `.free`.

### Change 4 — Watermark on free invoice PDFs

**File:** `Packages/BillableCore/Sources/BillableCore/Invoicing/InvoicePDFRenderer.swift`

Add a `watermark: String?` parameter to the renderer's input (default `nil`). When non-nil, draw the watermark text at the footer-center of every page:

```swift
// In InvoicePDFRenderer:
public struct InvoiceTemplateData {
    // ... existing fields ...
    public let watermark: String?  // nil = no watermark; "Sent with Cadence" = free user
}

// In the PDF draw routine, after the per-page content:
if let watermark = data.watermark {
    let footerY = pageHeight - 24  // 24pt from bottom
    let font = UIFont.italicSystemFont(ofSize: 9)
    let attrs: [NSAttributedString.Key: Any] = [
        .font: font,
        .foregroundColor: UIColor.systemGray2,
    ]
    let attributedString = NSAttributedString(string: watermark, attributes: attrs)
    let textSize = attributedString.size()
    let x = (pageWidth - textSize.width) / 2
    attributedString.draw(at: CGPoint(x: x, y: footerY))
}
```

(Adapt to whatever drawing primitive the existing renderer uses — `PDFKit`, `UIGraphicsPDFRenderer`, etc. The renderer's existing tests should be unchanged when `watermark == nil`.)

**Caller integration:**
- `InvoiceDetailView` and `InvoicePreviewView` both construct `InvoiceTemplateData`. They consult `SubscriptionManager.shared.canRemoveWatermark`. If `true`, pass `watermark: nil`. If `false`, pass `watermark: "Sent with Cadence"`.

**Watermark text:** literally `"Sent with Cadence"` — no URL, no marketing append.

**Watermark visual:** 9pt italic, system gray 2 (medium gray), centered horizontally, 24pt from the bottom of the page. On a multi-page invoice, the watermark appears on every page.

**Acceptance:**
- Free user issues an invoice → preview shows watermark. Open PDF in iOS Files → watermark visible on every page.
- Pro user issues an invoice → no watermark.
- During 7-day trial → no watermark (trial = same as Pro for watermark purposes).
- Renderer unit tests with `watermark: nil` pass unchanged.
- New renderer test: `watermark: "Sent with Cadence"` produces a PDF whose extracted text contains that string.

## 4. Schema / data model changes

**None.**

The entitlement state is derived from StoreKit's `Transaction.currentEntitlements` async sequence. No new `@Model`, no new persistent storage, no migration.

The PDF watermark is computed at render time from `SubscriptionManager.shared.canRemoveWatermark` — not stored on the `Invoice`. This means if a free user issues an invoice today and upgrades tomorrow, re-rendering the same invoice produces a watermark-free PDF. (Spec note: this is intentional — the watermark reflects current entitlement, not the entitlement at the moment of invoice creation.)

## 6. Risks

1. **Apple's intro offer eligibility logic is per Apple ID, not per device.** A user who uninstalls and reinstalls won't get a second trial. Document this clearly in the paywall copy or App Store listing. Not a fix — just an expectation to set.
2. **Watermark rendering could break PDF layout** if the existing renderer uses a fixed page footer area that overlaps with the new watermark Y. Mitigation: render a sample multi-page PDF during testing and visually inspect each page footer.
3. **Free-user-can-invoice changes invoice-creation telemetry.** If we eventually add analytics, the "invoice issued" event will now fire for free users too. Acceptable for v1.2; flag for the analytics design.
4. **Production legal URLs may not exist at ship time.** Spec lists this as a parallel user deliverable. If not ready, use placeholder hosted URLs (GitHub Pages) — never ship `example.com`.
5. **Edge case: user starts trial, cancels, reinstalls before trial expires.** Apple's behavior: trial state persists across reinstall (it's tied to the Apple ID transaction). No app-side handling needed.
