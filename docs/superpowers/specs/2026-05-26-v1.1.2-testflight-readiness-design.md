## 1. Summary

Cadence is one bug + three honesty edits away from being TestFlight-ready, and one currency-formatter sweep away from being globally App-Store-ready. This release ships exactly that — nothing more.

**Four pragmatic fixes:**

1. **StoreKit Subscribe button is grayed out.** Diagnose + fix the regression. Hard blocker — nobody can subscribe today.
2. **PDFs read "Unnamed business"** when Business Name is empty. Block the Send button + show a small banner when this happens. No new onboarding screen.
3. **Tagline + paywall copy lie.** "Get paid" / "paid in days, not weeks" — sweep all of it out of the codebase + FEATURES.md. Replace launch tagline with `"Track hours. Send invoices."`
4. **Currency is hardcoded USD.** Add a currency picker to Business Profile, auto-default from `Locale.current`, sweep every hardcoded `$` symbol out and replace with `NumberFormatter`-driven currency-aware formatting.

**Plus a QA pass** — run the full test suite, fix any failures, address deprecated-API warnings.

That's it. No new `@Model`, no forced onboarding screen, no free-tier redesign, no payment-provider integration, no Arabic RTL, no VAT, no Hijri dates.

The free-tier rebalance (trial + watermark + monthly meter) the original spec proposed is **explicitly deferred** to a later release. We'll learn from real TestFlight usage what conversion looks like before re-engineering the free experience.

## 3. Per-fix design

### Fix 1 — StoreKit Subscribe button grayed out

**Symptom:** Both paywall views (`"Send your first invoice"` and `"Go Pro"`) show Yearly/Monthly tier cards with spinning indicators next to price labels. Subscribe button is gray. No prices load. Prior session (task #4 in tracker) marked sandbox purchase completed — so this is a regression somewhere between then and now.

**Diagnosis path (in order):**
1. Open `Configuration.storekit` (the project's StoreKit Config file). Confirm two products exist with the IDs the code requests (likely `com.eldenstudios.billable.pro.yearly` and `…monthly`).
2. Confirm each product has a non-zero base price + localized prices for at least USD + SAR storefronts.
3. Confirm `SubscriptionService` (or whatever class wraps `Product.products(for:)`) requests the SAME product IDs that exist in the Config file.
4. Add a 5-second timeout on the price-loading state — if `Product.products(for:)` returns empty or errors, surface a tappable "Pricing unavailable — retry" message instead of an infinite spinner.

**Files involved:**
- `Billable/Configuration.storekit` (or equivalent path — exact path TBD during implementation)
- `Billable/Subscription/SubscriptionService.swift`
- `Billable/Views/PaywallView.swift`

**Acceptance:** Subscribe button enables within 2 seconds of opening either paywall. Sandbox purchase completes. Pro entitlement flips correctly.

### Fix 2 — "Unnamed business" PDF defense

**Symptom:** Business Profile starts empty after onboarding (`name = ""`). If user taps "+ New invoice" → fills time → Send, the PDF issuer field reads `Unnamed business`.

**Fix (minimal):**
1. **Disable the Send button** on `InvoiceGeneratorView` when `businessProfile.name.isEmpty`. Tapping it would have failed silently in production with embarrassing output.
2. **Show a yellow banner on Today** (or a header section) when `businessProfile.name.isEmpty`: `"Add your business name to send invoices →"` linking to Business Profile editor.
3. **No new onboarding screen.** No forced-setup gate. The banner + disabled-send is sufficient.

**Files involved:**
- `Billable/Views/InvoiceGeneratorView.swift` — disable Send + add inline hint
- `Billable/Views/TodayView.swift` — banner when name empty
- `BillableCore/.../BusinessProfile.swift` — verify `name` field exists + is observable

**Acceptance:** Fresh install with empty Business Profile → banner on Today, Send button disabled on InvoiceGenerator. Fill in name → banner disappears, Send button enabled.

### Fix 4 — Currency localization (USD-only → multi-currency)

**Current behavior:** All amounts show with hardcoded `$` prefix. Settings → Business Profile shows USD label (static, not user-editable).

**New behavior:**
1. **`BusinessProfile.currencyCode: String`** — verify the field exists in the model (default `"USD"`). If not, add it. ISO 4217 3-letter codes.
2. **Currency picker** in Business Profile editor. Searchable list of common currencies (USD, SAR, EUR, GBP, AED, EGP, JOD, KWD, BHD, QAR, OMR, CAD, AUD, INR, JPY, CNY) with full ISO list under "More".
3. **First-run default:** when Business Profile is first created (during onboarding), pre-fill `currencyCode = Locale.current.currency?.identifier ?? "USD"`. Saudi user gets SAR automatically.
4. **`Decimal.formatted(in:)` extension** in BillableCore — uses `NumberFormatter` with `currencyCode` set. Drop-in replacement for every `String(format: "$%.2f", value)` site in the app.
5. **Sweep** every hardcoded `$` symbol in views, PDF renderer, widgets, etc. Replace with the new formatter.
6. **PDF invoice** uses business currency for line items + totals.
7. **Out of scope:** exchange rates, multi-currency-per-invoice, currency conversion in Reports. Each invoice uses the business's current currency at issue time.

**Files involved (will be identified more precisely in the plan):**
- `BillableCore/.../Models/BusinessProfile.swift` — add `currencyCode` if missing
- `BillableCore/.../Money/Money.swift` — new file or extension on `Decimal`
- `Billable/Views/BusinessProfileEditor.swift` — currency picker
- `Billable/Views/TodayView.swift` — replace `$`
- `Billable/Views/InvoiceGeneratorView.swift` — replace `$`
- `Billable/PDF/InvoiceRenderer.swift` (or equivalent) — replace `$`
- `BillableWidgets/*` — replace `$` if used

**Acceptance:**
- Fresh install on `ar_SA` locale: Business Profile defaults to SAR.
- Switch to EUR via picker: all amounts re-render as `€…`.
- PDF rendered with SAR shows SAR throughout.
- Grep returns zero hardcoded `$` outside of test fixtures + the StoreKit price display (which is correctly handled by StoreKit itself, not us).

## 7. Risks

1. **StoreKit Config edit could break existing sandbox state.** Mitigation: implement in a worktree; verify sandbox purchase in isolated simulator before merging.
2. **Hardcoded `$` sweep could miss some sites.** Mitigation: run `git grep -E "\\\$[0-9]|String\\(format: \"\\\$|\\\$\\(" -- "*.swift"` after sweep; visual inspection of all top-level views.
3. **`Locale.current.currency` returns weird values on simulator** (e.g., simulator might default to USD even on `ar_SA` if region wasn't set). Mitigation: fall back to USD safely + test on real device before submission.
4. **Currency formatting in PDF renderer** may break PDF layout if the formatted string is significantly wider than `$1,234.56`. Mitigation: render test PDFs with longest-currency-codes (SAR, KWD with 3 decimals) and verify column widths.

## 8. App Store submission checklist (user's parallel work, NOT code)

These are blockers for actual App Store launch — separate from the code work above. Listed here so they don't get forgotten:

- [ ] **Privacy Policy URL** — host any URL (GitHub Pages, Notion published page, custom domain). Mandatory.
- [ ] **Terms of Use URL** — mandatory for any auto-renewing subscription per Apple Schedule 2.
- [ ] **App Privacy answers** in App Store Connect — declare what data is collected (Cadence: probably none beyond CloudKit, which is iCloud-internal).
- [ ] **App Store screenshots** — required sizes: 6.7" (iPhone 17 Pro Max), 6.5" (older Pro Max), 5.5" (older iPhone Plus). 3-10 per size.
- [ ] **App Store listing copy** — name, subtitle, description, promotional text, keywords (max 100 chars), support URL, marketing URL (optional).
- [ ] **Age rating questionnaire** — straightforward for Cadence (no objectionable content).
- [ ] **App icon** at all required sizes — likely already configured.
- [ ] **Build uploaded to App Store Connect** — `xcodebuild archive` + Organizer → Distribute.
- [ ] **TestFlight internal testers** added (your email + any friends) — auto-approved.
- [ ] **(Optional) TestFlight external testers** — requires beta review (~1-2 days).
- [ ] **Submit for App Store review** — usually 24-48 hours; standard review.

These can happen in parallel with the code work. Recommend drafting Privacy Policy + Terms of Use now (or using a standard generator), staging assets, and writing App Store copy.
