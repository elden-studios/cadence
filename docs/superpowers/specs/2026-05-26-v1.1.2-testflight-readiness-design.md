# Cadence v1.1.2 — TestFlight Readiness

**Status:** Design approved · ready for implementation plan
**Date:** 2026-05-26
**Phase:** v1.1.2 (post-v1.1.1, post-v1.2-archived)
**Estimated scope:** ~3-5 working days
**Spec author session:** comprehensive app assessment + decision pass (no full brainstorm — user opted to go straight to spec)

---

## 1. Summary

A focused bug-fix and polish release to make Cadence ready for its first real TestFlight build. Five concrete P0 fixes derived from a hands-on app assessment:

1. **StoreKit pricing regression** — the Subscribe button is currently grayed out with no prices loaded on either tier. No one can subscribe. This is a hard blocker for TestFlight.
2. **Free-tier rebalance** — current free tier (track + 2 clients, no invoicing) is too restrictive; free users hit the wedge paywall on first invoice attempt and churn immediately. Move to **14-day full Pro trial + freemium with 1 invoice/month + watermark on free PDFs**.
3. **Forced Business Profile onboarding** — current onboarding lets users skip Business Profile, so first-issued PDFs read "Unnamed business" in the issuer field. Force the setup as a first-run step (no skip).
4. **Tagline + copy sweep** — drop all "get paid" / "paid in days, not weeks" messaging. Replace launch tagline with `"Track hours. Send invoices."` Sweep paywall, App Store metadata, marketing screens. Aligns app messaging with what it actually does today (no in-app payments).
5. **Currency localization** — currently USD-only. Add a currency picker in Business Profile, defaulting to `Locale.current.currency.identifier`. Format all amount displays via `NumberFormatter` with the current currency code. Persist on `BusinessProfile`.

Two non-feature companion items:
- **UX gap list (timeline gestures, reminder defaults, segments, iCloud status, etc.)** — explicitly deferred to v1.1.3.
- **Payment links integration (PayTabs)** — explicitly deferred to a separate v1.x release; out of scope here.

## 3. Per-P0 design

### P0-1: StoreKit pricing regression

**Symptom:** Subscribe button is grayed out on both the invoice paywall ("Send your first invoice.") and the Settings → Upgrade to Pro paywall ("Go Pro."). Yearly and Monthly tier cards show spinners next to the price labels but never resolve.

**Suspected causes** (in order of likelihood):
1. `StoreKit Configuration` file (in the project) is missing prices, OR product IDs in `Configuration.storekit` don't match what `SubscriptionService` requests via `Product.products(for:)`.
2. The Storekit Config file's localized prices array is empty for the user's current `Locale.current` (i.e. defined for US but the simulator is running in another region — possibly KSA).
3. `Product.products(for:)` is failing silently (network sandbox issue) and the UI is sitting on the loading state with no error surface.

**Fix steps:**
1. **Audit** the `Configuration.storekit` file. Confirm:
   - Two products exist: `com.eldenstudios.billable.pro.yearly` and `com.eldenstudios.billable.pro.monthly` (or whatever IDs `SubscriptionService` expects).
   - Each has a base price + localized prices for the user's target storefronts (at minimum: USD for US, SAR for KSA, EUR for EU).
   - Each is configured as an **auto-renewable subscription** in the same Subscription Group.
   - Add a **14-day free trial** intro offer to both — this is P0-2's mechanism.
2. **Audit** `SubscriptionService` / `PaywallView`:
   - The product IDs in code must match `Configuration.storekit`.
   - The loading state should have a 5-second timeout and surface an error message ("Pricing unavailable — please retry") instead of an infinite spinner.
3. **Smoke test** in simulator: open paywall, expect prices to load within 2 seconds. Tap Subscribe with sandbox account.

**Files involved:**
- `Billable/Configuration.storekit` (or equivalent path)
- `Billable/Subscription/SubscriptionService.swift`
- `Billable/Views/PaywallView.swift`

**Acceptance:** Subscribe button enables within 2 seconds of paywall open. Sandbox purchase completes. Entitlement flips to Pro.

### P0-2: Free-tier rebalance (14-day trial + 1/mo freemium + watermark)

**Current model:**
- Free: time tracking, up to 2 active clients, no invoicing, no reports.
- Pro: everything unlimited.

**New model:**
- **First 14 days after install:** full Pro entitlement (a StoreKit intro offer is the cleanest implementation — automatic, App Store handles the trial timer).
- **After trial expires:**
  - **Free:** unlimited time tracking, unlimited clients & projects, **1 outgoing invoice per calendar month**, watermark on free PDFs ("Sent with Cadence"), no Reports tab.
  - **Pro:** everything unlimited, no watermark, full Reports.

**Why this model** (research summary):
- B2C productivity apps overwhelmingly use trial-then-freemium, not pure trial or pure freemium.
- Apple's App Store explicitly supports auto-renewable subscriptions with free trial intro offers — clean StoreKit 2 implementation.
- 1 invoice/month is meaningful enough to drive conversion (most freelancers issue 2-10/mo) but generous enough that hobby users stick around.
- Watermark creates organic social pressure: client sees "Sent with Cadence" footer, freelancer feels unprofessional, upgrades to remove.

**Implementation:**

1. **StoreKit Config — add intro offer.** Both Yearly and Monthly products get a 14-day free trial intro offer. App Store handles the timer; user is auto-charged on day 15 unless they cancel. (Apple allows this without a "trial agreement" overlay since the intro offer is explicit.)

2. **New model: `FreeTierMeter`** in BillableCore. Singleton @Observable.
   ```swift
   @Model final class FreeTierMeter {
       var monthKey: String  // "2026-05" — current calendar month
       var invoicesIssuedThisMonth: Int
       var lastTrialEndAt: Date?  // mirrored from StoreKit transaction
   }
   ```
   `invoicesIssuedThisMonth` is incremented on `Invoice.markSent`. Reset to 0 when `monthKey` doesn't match the current month.

3. **Updated entitlement logic** in `SubscriptionService`:
   ```swift
   enum Entitlement {
       case proTrial(daysRemaining: Int)
       case pro
       case free(invoicesAvailableThisMonth: Int)  // 0 or 1
   }
   ```
   `free(invoicesAvailableThisMonth: 0)` blocks invoice send + shows the paywall. `free(invoicesAvailableThisMonth: 1)` allows send with watermark.

4. **PDF watermark** on free invoices: a footer text "Sent with [Cadence logo] cadence.app" in 9pt italic gray. Implemented in `InvoiceRenderer.swift` (the existing PDF generator) — append-if-not-pro.

5. **Paywall copy updates** (P0-4 sweep covers this too):
   - "Send your first invoice." → "Send unlimited polished invoices" (or similar)
   - "Track hours, get paid fast" → "Track hours, invoice in 60 seconds"
   - Pricing tier subtitle: "First 14 days free, then $X/mo"

**Files involved:**
- `Billable/Configuration.storekit` — add intro offer
- `BillableCore/Sources/BillableCore/Models/FreeTierMeter.swift` — new file
- `BillableCore/Sources/BillableCore/Subscription/SubscriptionService.swift` — new Entitlement enum
- `BillableCore/Sources/BillableCore/Invoice/InvoiceStatusMachine.swift` — increment meter on markSent
- `BillableCore/Sources/BillableCore/Invoice/InvoiceRenderer.swift` (or PDF gen path) — watermark footer
- `Billable/Views/PaywallView.swift` — copy + intro-offer-aware tier card subtitle
- `Billable/Views/InvoiceGeneratorView.swift` — meter-aware Send button (disabled or paywall-trigger when free + 0 invoices left this month)

**Acceptance:**
- Fresh install: open paywall, see "First 14 days free" subtitle. Tap Subscribe with sandbox account, see entitlement flip to `.proTrial`.
- During trial: invoice send works without watermark, Reports unlocked.
- Day 15 (simulated by manipulating StoreKit Config trial duration to 1 hour for testing): entitlement flips to `.free(invoicesAvailableThisMonth: 1)`. Issue an invoice → succeeds, has watermark, meter becomes 0.
- Issue a second invoice → blocked, paywall opens.
- First of next month: meter resets to 1.

### P0-3: Force Business Profile setup as onboarding

**Current behavior:** New users hit the 3-page onboarding (per memory), tap "Get started", land on Today. Business Profile is empty (`name = ""`, etc.). If they tap "+ New invoice" before filling Business Profile in Settings, the issuer field reads "Unnamed business".

**New behavior:** After the 3-page onboarding, add a **mandatory Business Profile setup screen** before landing on Today. Required fields: business name, currency. Optional: email, phone, address.

Implementation:
1. **New view:** `Billable/Views/Onboarding/BusinessProfileSetupView.swift`
   - Form with: Business Name (required), Currency (picker, defaults from Locale), Email (optional), Phone (optional), Address (optional).
   - "Continue" button disabled until Business Name is non-empty.
   - No "Skip" button.
2. **Onboarding flow update:**
   - Existing 3-page onboarding → `OnboardingFlowView` shows 3 pages → "Get started" → push `BusinessProfileSetupView` → "Continue" → seal onboarding-complete flag → land on Today.
3. **Recovery banner on Today** (defense in depth): if for any reason `BusinessProfile.name` becomes empty later (data corruption, CloudKit edge case), show a yellow banner on Today: "Add your business name before sending invoices →" linking to the Business Profile editor.
4. **Block invoice send when name is empty:** if user somehow ends up at Send with an empty business name, the Send button shows a Settings-redirect instead of the share sheet.

**Files involved:**
- `Billable/Views/Onboarding/BusinessProfileSetupView.swift` — new
- `Billable/Views/Onboarding/OnboardingFlowView.swift` — append step
- `Billable/Views/TodayView.swift` — add empty-business banner
- `Billable/Views/InvoiceGeneratorView.swift` — block Send if business name empty
- `Billable/State/AppEnvironment.swift` (or equivalent) — onboarding-complete flag now requires Business Profile complete

**Acceptance:**
- Fresh install: cannot reach Today without setting Business Name.
- Manually emptying the Business Name (via Settings → Business profile → Save with empty name should be blocked, but if it slips through): yellow banner on Today, Send button disabled.

### P0-5: Currency localization (USD-only → multi-currency)

**Current behavior:**
- All amounts display as `$X.XX` (hard-coded USD with `$` prefix or `NumberFormatter` set to USD).
- Settings → Business profile shows "USD" but probably as a non-editable static label.

**New behavior:**
1. **`BusinessProfile.currencyCode: String`** (ISO 4217 — "USD", "SAR", "EUR", etc.) — already may be a field; verify in current model.
2. **Currency picker in Business Profile editor** — a `Picker` over the ~30 most-likely currencies (USD, SAR, EUR, GBP, AED, EGP, JOD, KWD, BHD, QAR, OMR, CAD, AUD, INR, JPY, CNY, etc.) with full ISO list under "More" if needed.
3. **Default currency on first run** = `Locale.current.currency?.identifier ?? "USD"`. This is the value the BusinessProfileSetupView (P0-3) pre-fills.
4. **Format amounts** via `NumberFormatter` with `currencyCode = businessProfile.currencyCode`. Implemented as `Money.formatted(in: businessProfile.currencyCode)` extension on `Decimal`. Replace every `String(format: "$%.2f", ...)` and `"$\(amount)"` with `amount.formatted(in: profile.currencyCode)`.
5. **PDF invoice** uses the business currency for line items + totals.
6. **No exchange rates / multi-currency-per-invoice.** Each invoice uses the business's currency at time of issue.

**Files involved:**
- `BillableCore/Sources/BillableCore/Models/BusinessProfile.swift` — confirm `currencyCode` field
- `BillableCore/Sources/BillableCore/Money/Money.swift` (or new) — `Decimal.formatted(in: currencyCode)` extension
- `Billable/Views/BusinessProfileEditor.swift` — currency picker
- `Billable/Views/Onboarding/BusinessProfileSetupView.swift` — currency picker pre-filled from Locale
- `Billable/Views/TodayView.swift` — replace hardcoded `$` with currency-aware formatter
- `Billable/Views/InvoiceGeneratorView.swift` — replace hardcoded `$`
- `Billable/PDF/InvoiceRenderer.swift` — replace hardcoded `$`

**Acceptance:**
- Fresh install with simulator Locale = `ar_SA`: BusinessProfileSetupView pre-selects SAR. Amounts display as `SAR 1,234.56` (or `١٬٢٣٤٫٥٦ ر.س` in Arabic locale — formatter respects locale).
- Switch currency picker to EUR: all amounts re-render as `€1,234.56`.
- PDF invoice issued with SAR shows SAR consistently.

## 6. Risks

1. **StoreKit Config edit could break existing test purchases.** Mitigation: do P0-1 fixes in a worktree, verify in sandbox, then merge.
2. **Free-tier rebalance changes user expectations.** No real users yet (pre-TestFlight), so this risk is theoretical, but document the change in App Store release notes when shipping.
3. **PDF watermark placement could be ugly with long footers.** Mitigation: design review of the watermark before merging — render a sample PDF and screenshot it.
4. **Forced onboarding adds friction.** Trade-off: friction now vs. "Unnamed business" PDFs forever. Forced onboarding wins.
5. **Currency picker performance.** With 150+ ISO currencies, the picker should be searchable, not a flat scroll list. Implement with a search field.
